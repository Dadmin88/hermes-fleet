# Hermes Fleet v0.1.0 Implementation Plan

> **For Hermes:** Execute phase-by-phase with strict TDD, one implementation writer at a time, then spec and quality review at each checkpoint.

**Goal:** Build a standalone `hermes-fleet` general plugin that inventories configured Hermes A2A nodes, checks health, dispatches bounded parallel tasks, records local history, and exposes the same behavior through `hermes fleet ...` and model-callable tools.

**Architecture:** The plugin owns operator-readable YAML/JSON/JSONL state under the active `HERMES_HOME/fleet/`. Domain modules depend on a narrow `FleetTransport` protocol; the only wire implementation is an async `httpx` A2A v1.0 client. The controller remains the only Fleet-aware node; remote nodes use Hermes' native A2A platform.

**Tech Stack:** Python 3.11+, Hermes general plugin API, `httpx`, PyYAML, `pytest`, `pytest-asyncio`, `ruff`.

## Confirmed Phase 0 Baseline

- Current Hermes source: `/home/kyle/.hermes/hermes-agent`, clean `main`, inspected at `a991dfc25`.
- General plugin contract: `plugin.yaml` + `__init__.py::register(ctx)`; `ctx.register_tool`, `ctx.register_cli_command`, `ctx.register_command`, and `ctx.register_skill` are available.
- Async model tools are supported through `ctx.register_tool(..., is_async=True)`.
- Native A2A platform exists at `plugins/platforms/a2a/` and serves A2A v1.0 Agent Cards and JSON-RPC.
- Canonical discovery: `GET /.well-known/agent-card.json`.
- Canonical task method: `SendMessage`; legacy `message/send` is accepted.
- `contextId` belongs inside the Message. Canonical task/context fields are `id` and `contextId`.
- Hermes' bundled outbound helper is internal, synchronous `urllib`, accepts arbitrary URLs, and stores token values in `config.yaml`; Fleet must not depend on it.
- Transport decision: implement only the minimal A2A v1.0 client with `httpx` behind `FleetTransport`. Do not add SDK/runtime fallbacks.

## Scope Guard

In scope: explicit node registry, discovery/health, exact/tag selection, one/many task dispatch, local cache/history, CLI, four model tools, optional `/fleet`, operator skill, doctor, docs, tests, clean install, real-node demo.

Out of scope: dashboard, daemon, custom protocol, automatic discovery, scheduler, workflow engine, distributed queue/database, file sync/transfer, remote shell, shared memory, durable jobs, controller-restart recovery, automatic retries of ambiguous submissions.

## Primary Risks

1. A2A v1.0 response wrappers and older aliases differ; keep tolerance in the transport parser only.
2. HTTP timeout after request write is ambiguous; never retry automatically.
3. Hermes plugin loader APIs evolve; registration tests must use the live public `PluginContext` contract.
4. Secret helper may be unavailable outside Hermes; fallback must preserve unrelated `.env` content and permissions.
5. Android sleep can make the real three-node gate nondeterministic; treat offline as a valid Fleet result but not as proof of full demo completion.
6. Existing Hermes `a2a_agents` permits inline secrets and arbitrary URL tools; Fleet must not reuse those model-facing semantics.
